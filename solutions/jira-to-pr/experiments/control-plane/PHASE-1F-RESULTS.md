## Trust boundaries

Schema versions 5 through 8 bind each observation and PR body update to the workflow, candidate, verification, publication, PR identity, and exact head commit. Required check name and GitHub App slug come from an immutable, separate trusted policy snapshot. A deferred PostgreSQL gate rejects `PASS` without exactly one successful record for each required exact-head check and enough current-head approvals from each reviewer's latest review. Observation reads the draft PR, base, branch, and commit tree before and after collecting check and review metadata. Unknown GitHub responses fail closed.

Reviews and inline review comments are classified before storage or agent input. Raw bodies and CI logs are never stored in PostgreSQL. Only the exact allowlisted review code and trusted check remediation code can become repair input; other current-head review prose requires human attention. The repair input has a durable digest and idempotency key before Agents API submission. The new `CredentialProvider` interface preserves token isolation while allowing a future scoped GitHub App installation-token provider without changing publisher logic. Automatic merge and Jira integration are absent.
