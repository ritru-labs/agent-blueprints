# Operator handoff and live qualification

AWS credentials are deferred by the user. Implementation and credential-free validation proceed independently. Do not inspect unrelated profiles or attempt customer cloud access. Supply configuration names, approved scopes, and endpoint names through trusted configuration; never send secret keys in chat or commit them.

## Local evidence

Install the locked Python environment, build the pinned compiler image, run the control and real dependency suites, and prepare the included network inventory. Restart preparation and acknowledge its exact digest. Verify the generated project, import manifest, expected inputs, checksums, and explicit execution-disabled status. Fixture models/adapters are fixture evidence only.

The local Docker daemon can prevent container creation if its shared storage becomes read-only. Preserve other projects and use an isolated CI runner for verification; do not prune or restart shared infrastructure without authorization.

## Read-only AWS campaign

Authorize a disposable account and explicit regions/profile. Verify STS identity independently and compare VPC/subnet configurations with the AWS console/API, including DNS flags, CIDRs, tenancy, subnet addressing, tags, ownership, and dependencies. Exercise pagination, denied reads, unsupported configurations, throttling, and budget exhaustion. Discovery is partial; a trusted scoped assessment must resolve ownership and coverage before any migration can pass execution gates. Absence of CloudFormation tags does not prove manual ownership.

## Model campaign

Authorize the provider/model/HTTPS endpoint and its retention policy. Run typed review with official documents. Verify complete alias coverage, input minimization, bounded persisted call budgets, structured usage receipts, and rejection of injected/malformed proposals. A model recommendation cannot replace configuration checks or grant approval. Missing model configuration remains an explicit untested state.

## Destination and runner campaign

A trusted administrator provisions an approved existing destination stack for the generated `infra-migration-generated` project, exact account/region, encrypted backend, and protected state directory. Bootstrap is not automated. Qualify the immutable Pulumi image, enforced network egress, short-lived credential broker, backend secret handling, output redaction, and malicious-code containment. The AWS read lease does not create IAM permissions; source transfer requires a separately scoped authorized client.

## Manual adoption campaign

Use a small known-manual IPv4 VPC/subnet fixture with independently observed baseline, frozen writers, explicit coverage and ownership evidence, and resource/application health checks. Independently qualify the adapter before administrative admission. Review and approve each exact bounded operation. Inject drift, concurrent approvals, expired authorizations, interruption before and after submission, partial import, and unknown outcomes. Preserve IDs/configuration/protection and require explained zero-change preview. Reconcile unknown outcomes without replaying writes.

## CloudFormation campaign

Use a source fixture with supported references and no exports, custom resources, nested stacks, transforms, or unsupported semantics. Freeze source automation. Review policy-only retention changes, verify deployed retention, then separately approve resource release. Validate actual change-set actions, exact physical IDs, retained infrastructure, destination import, and health. Inject failures at every ownership stage. Demonstrate resource-specific recovery; do not claim universal re-adoption or delete a whole source stack.

## Production acceptance

Deploy and qualify the implemented authenticated preparation service, tenant-bound identities and PostgreSQL approval/operation storage; implement and deploy broker and runner policies, encrypted evidence retention, monitoring, backups, restore and incident procedures. Review trust boundaries independently and run customer acceptance/load/recovery campaigns against immutable source. Keep supported resource/framework scope explicit. Principal constructors, adapter allowlists, freeze/health callbacks, and checkpoint access belong to trusted services; none are model-controlled authority. Credentials alone do not satisfy these gates.

Authenticated preparation service commands and remaining deployment gates are documented in [service deployment](service-deployment.md). No cloud credentials are required for its automated campaign. The [operator dashboard](dashboard.md) is served at the service root and has a real browser campaign.
